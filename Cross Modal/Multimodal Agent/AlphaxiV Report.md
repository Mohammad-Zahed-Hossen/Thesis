## A. Executive verdict

- **Candidate 2 is scientifically alive, but the broad idea is already occupied.** By 2025–2026, [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918), [VTool-R1](https://www.alphaxiv.org/abs/2505.19255), [ACTIVE-o3](https://www.alphaxiv.org/abs/2505.21457), [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475), [VISUALTOOLBENCH](https://www.alphaxiv.org/abs/2510.12712), and [TIR-Bench](https://www.alphaxiv.org/abs/2511.01833) already cover dynamic visual acquisition, tool-enabled reasoning, budget-aware behavior, and tool-choice failures.
- **The exact undergraduate-sized gap is not “learn when to use tools.”** [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) explicitly defines a Tool Benefit Score as the difference between tool-enabled and tool-disabled accuracy and trains a policy to use tools only when they help. It is therefore direct occupation of the proposed novelty claim. [Tool Benefit](https://www.alphaxiv.org/abs/2512.16918?page=1)
- **A narrower gap remains around externally valid, counterfactual tool-value measurement.** Existing work usually compares complete systems, tool-enabled versus tool-disabled variants, or accuracy and call counts. It rarely provides a clean per-instance causal estimate of whether a particular call changed an incorrect answer into a correct one without introducing confounds from extra context, extra tokens, or altered decoding.
- **A reproducible dataset-level benchmark exists.** [ActiView](https://www.alphaxiv.org/abs/2410.04659) is the simplest active-perception benchmark: 314 source questions, 1,625 evaluation instances, objective VQA answers, and zooming/shifting pipelines. Its repository is linked by the authors as [THUNLP-MT/ActiView](https://github.com/THUNLP-MT/ActiView). [Benchmark](https://www.alphaxiv.org/abs/2410.04659?page=2)
- **The most suitable new benchmark for tool necessity is probably not a full web agent.** [VISUALTOOLBENCH](https://www.alphaxiv.org/abs/2510.12712) supports cropping, image processing, web search, calculators, and multi-turn tasks, but its open-ended rubric evaluation relies heavily on an LLM grader. [TIR-Bench](https://www.alphaxiv.org/abs/2511.01833) has deterministic answers but deliberately constructs tasks that require tools, so it is poorly suited to studying unnecessary tool calls.
- **The environment burden is acceptable only if the thesis is restricted to local image tools.** Crop, resize, OCR, and deterministic image transforms can be implemented as a dataset → model → tool loop. Web search introduces API dependence, changing web content, provenance problems, latency, and contamination risk.
- **Commercial API access is useful for baselines and auditing, not necessary for the core intervention.** It enables comparisons against o3/Gemini/GPT-class agents, but an undergraduate thesis should not make its central claim depend on an inaccessible or expensive proprietary policy.
- **Classification: RESERVE.** Candidate 2 should not displace a turnkey fallback yet. It becomes competitive only if narrowed to a controlled, deterministic study of unnecessary versus necessary visual actions, with a fixed action budget and counterfactual evaluation.

The matrix shows three important distinctions.

First, **tool selection is already being learned**, not merely prompted. [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) uses adaptive reward based on whether tools improve performance, while [ACTIVE-o3](https://www.alphaxiv.org/abs/2505.21457) learns region proposals through RL.

Second, **tool necessity and tool value are not identical**. [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) defines a dataset-level benefit score using repeated executions of a reference model. That is a useful operational proxy, but it is not a causal intervention estimate for every agent trajectory. The score can be affected by stochasticity, model choice, prompt choice, and the fact that tool-enabled and tool-disabled runs have different context lengths.

Third, **existing work does not yet provide a universally accepted evaluation protocol for unnecessary tool use**. [VISUALTOOLBENCH](https://www.alphaxiv.org/abs/2510.12712), for example, reports proactivity, validity, and volume, but explicitly defines success largely as whether a tool call returns a valid result—not whether the call was useful. ### Most turnkey benchmark: ActiView

[ActiView](https://www.alphaxiv.org/abs/2410.04659) is the best operational starting point because it reduces the problem to:

```text
image + question
        ↓
direct answer or select views
        ↓
deterministic view construction
        ↓
answer
        ↓
exact accuracy and view-selection metrics
```

It avoids the second, much riskier pattern:

```text
browser/simulator → stateful agent → external tool
        ↓
new observation → new action → termination
```

The benchmark is not perfect. It has manually curated views and visual-clue annotations, so it may measure instruction following and clue localization more than general open-world active perception. It also does not naturally include OCR, web retrieval, clarification, abstention, or economic costs. Nevertheless, those limitations are preferable to a fragile environment for an undergraduate thesis.

## E. Gap destruction

### Gap 1: “Agents do not know when to use tools”

**Initial hypothesis:** multimodal agents can call tools but do not know whether a tool will improve the answer.

**Closest prior work:** [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) directly defines and trains on tool benefit. [VTool-R1](https://www.alphaxiv.org/abs/2505.19255) also allows a direct answer or one visual action and reports that models become more selective during RL. [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475) documents underuse of image search.

**Later work:** [ToolGate](https://www.alphaxiv.org/abs/2606.03054), [To Call or Not to Call](https://www.alphaxiv.org/abs/2605.00737), [Scores Are Not Decisions](https://www.alphaxiv.org/abs/2607.27083), and [CoBRA](https://www.alphaxiv.org/abs/2609.00967) indicate that general tool-call boundaries and cost-aware stopping are now active research topics.

**What remains:** a small, independently reproducible benchmark separating:
- direct-answer correctness;
- tool necessity;
- tool usefulness;
- tool harm;
- call cost;
- stop quality.

**Confidence that the broad gap is open:** LOW.  
**Confidence that a rigorous evaluation protocol remains open:** MEDIUM-HIGH.

### Gap 2: “No one measures counterfactual tool value”

**Initial hypothesis:** papers report final accuracy after tool use but never ask whether the call actually mattered.

**Closest prior work:** [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) runs tool-enabled and tool-disabled reference-model evaluations to compute $\Delta S$. [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475) compares no-search, image-search, text-search, full rollout, and SoM conditions. [VTool-R1](https://www.alphaxiv.org/abs/2505.19255) reports direct, prompted tool-use, and trained tool-use baselines.

**What remains:** those are system-level or reference-model comparisons. They do not fully isolate:
- whether the specific call supplied decisive evidence;
- whether the same answer could have been reached without the call;
- whether the call helped because of the transformed image or merely because it generated more tokens;
- whether the call corrected an error or introduced a new one.

**Confidence:** MEDIUM. This is the strongest surviving gap, but it is a measurement contribution rather than a novel learning algorithm.

### Gap 3: “Tool use should be uncertainty-aware”

**Initial hypothesis:** an agent’s calibrated uncertainty should predict whether to zoom, search, OCR, or abstain.

**Prior work:** the reviewed multimodal papers mostly use outcome rewards, heuristic rewards, or implicit model reasoning. [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) uses benefit labels but does not present a standard calibration analysis of the decision probability. [ActiView](https://www.alphaxiv.org/abs/2410.04659) measures view selection, not confidence calibration. [Budget-Aware Tool Use](https://www.alphaxiv.org/abs/2511.17006) uses budget state but not multimodal epistemic uncertainty.

**What remains:** calibration of the *action decision*, not merely answer confidence:
- probability that direct answering is correct;
- probability that zooming changes the answer;
- probability that OCR is useful;
- probability that abstention is preferable.

**Confidence:** MEDIUM. This is plausible, but the contribution must be framed as measurement or a lightweight router, not as the discovery of uncertainty-aware tool use.

### Gap 4: “Agents do not stop at the right time”

**Initial hypothesis:** agents either stop too early or continue with redundant calls.

**Prior work:** [ActiView](https://www.alphaxiv.org/abs/2410.04659) has a “do you require more information?” pipeline. [VTool-R1](https://www.alphaxiv.org/abs/2505.19255) allows direct answering instead of acting. [Budget-Aware Tool Use](https://www.alphaxiv.org/abs/2511.17006) explicitly studies budgets and stopping behavior. [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475) observes that incorrect trajectories may contain more calls than correct ones.

**What remains:** a stopping metric based on marginal answer improvement:
$$
\Delta U_t =
\Pr(\text{correct after another action})
-
\Pr(\text{correct now})
-
\lambda \cdot \text{cost(action)}.
$$

**Confidence:** MEDIUM-LOW. The idea is occupied in general tool agents; only a multimodal deterministic implementation may remain defensible.

### Gap 5: “No benchmark distinguishes perception, selection, execution, and final-answer errors”

**Initial hypothesis:** current scores collapse all agent failures into final accuracy.

**Prior work:** [VISUALTOOLBENCH](https://www.alphaxiv.org/abs/2510.12712) records tool validity and volume; [TIR-Bench](https://www.alphaxiv.org/abs/2511.01833) has deterministic task outputs; [ActiView](https://www.alphaxiv.org/abs/2410.04659) has view-selection metrics; [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475) provides qualitative failure analysis.

**What remains:** a controlled intervention matrix where the same question is evaluated with:
1. original image;
2. oracle crop;
3. model-selected crop;
4. corrupted crop;
5. successful tool output;
6. failed tool output.

**Confidence:** MEDIUM-HIGH. This is the most defensible thesis-shaped evaluation contribution.

## F. Candidate research questions

### RQ1: Counterfactual visual-tool utility

**Condition/intervention:** On [ActiView](https://www.alphaxiv.org/abs/2410.04659) and a deterministic crop/OCR subset of [TIR-Bench](https://www.alphaxiv.org/abs/2511.01833), compare direct answering, fixed tool use, model-selected tool use, and oracle-selected tool use under matched model and token budgets.

**Outcome:** tool-value classification accuracy, answer accuracy, unnecessary-call rate, missed-necessary-call rate, and cost-adjusted utility.

**Comparison:** direct answering and fixed workflows.

**Evaluation setting:** held-out questions grouped into direct-solvable, tool-helpful, tool-neutral, and tool-harmful strata.

This is the strongest RQ.

### RQ2: Calibration of the “call or answer” decision

**Condition/intervention:** Add a lightweight router that predicts whether crop/zoom/OCR will improve the answer, using direct-answer confidence, disagreement across stochastic samples, and image-resolution/task metadata.

**Outcome:** selective accuracy, risk–coverage curve, expected calibration error of the action decision, and cost at fixed accuracy.

**Comparison:** always direct, always tool, prompted VLM choice, and [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918)-style benefit labels where feasible.

**Evaluation setting:** ActiView plus held-out TIR-Bench tasks with deterministic answer checking.

### RQ3: Failure decomposition for multimodal tool decisions

**Condition/intervention:** Evaluate the same agent with oracle and predicted tool parameters, oracle and predicted tool choice, and tool outputs independently verified.

**Outcome:** proportion of errors attributable to perception, tool selection, parameterization, execution, evidence interpretation, stopping, and final answer generation.

**Comparison:** direct VLM, fixed crop workflow, prompted agent, and lightweight router.

**Evaluation setting:** local image-only tools, no web browser.

RQ3 has higher evaluation value than algorithmic novelty and is more likely to produce a meaningful negative result.

## G. Minimal experiment

### Experiment for RQ1

- **Dataset:** 200–300 held-out examples from [ActiView](https://www.alphaxiv.org/abs/2410.04659), plus 100–200 deterministic crop/rotation/OCR examples from [TIR-Bench](https://www.alphaxiv.org/abs/2511.01833).
- **Models:** Qwen2.5-VL-7B or a comparable open-weight VLM; one commercial model such as Gemini or GPT as an external baseline.
- **Baseline:** direct answer; always crop; fixed human-annotated crop; prompted “use tools if helpful” agent.
- **Intervention:** a binary or multiclass router choosing `direct`, `crop`, `OCR`, or `abstain`.
- **Controls:** identical image resolution, prompt family, temperature, maximum output tokens, and maximum action count.
- **Metrics:** answer accuracy, unnecessary invocation rate, necessary-tool recall, harmful-tool rate, average calls, latency, and cost-adjusted utility.
- **Ablations:** confidence-only router; image-resolution-only router; random action; oracle action; tool output removed after selection.
- **Runtime:** a 50–200 sample pilot is feasible in one day with local inference or a few hundred API calls. Full experiments may require several thousand calls.
- **API dependence:** optional for the core experiment; useful for one strong reference baseline.
- **Failure fallback:** if the router does not improve accuracy, report the measured prevalence and predictability of tool benefit.

### Experiment for RQ2

- Train no large model. Use logistic regression, gradient boosting, or a small MLP over:
  - direct-answer confidence;
  - vote agreement across 3–5 samples;
  - answer entropy;
  - image dimensions;
  - OCR-like visual density;
  - question type;
  - direct-answer consistency under resized inputs.
- Define “tool-helpful” using a fixed reference model and oracle deterministic tool outputs.
- Evaluate risk–coverage and cost–accuracy curves.
- Use a question-level split and source-image split to reduce leakage.
- Report calibration separately for “tool helpful” and “tool harmful.”
- Negative result: show that answer confidence is poorly predictive of tool benefit.

### Experiment for RQ3

Construct a $4\times4$ error intervention matrix:

| Component | Oracle condition | Predicted condition |
|---|---|---|
| Perception | Full-resolution or oracle crop | Original model input |
| Tool choice | Oracle useful tool | Agent-selected tool |
| Parameters | Ground-truth crop/OCR parameters | Predicted parameters |
| Execution | Verified output | Real execution with failures |
| Final answer | Ground-truth evidence supplied | Model-interpreted evidence |

The difference between conditions estimates where performance is lost. This can produce a scientific result even if no proposed router improves the final answer.

The candidate passes the plug-and-play gates only after removing web browsing and large-scale RL. It fails the gate if the intended thesis requires reproducing [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) training, recreating [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475)’s live-search environment, or using open-ended LLM judging as the primary metric.

## I. What could kill this candidate?

1. **The broad novelty claim is already occupied.** [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) is too close to “learn when tool use actually helps” to ignore.
2. **Tool necessity may be circularly defined.** If “necessary” means that a reference model improved with a tool, the label measures the reference model’s weakness rather than objective information necessity.
3. **Benchmark construction may leak the answer.** Human-selected “tool-required” examples, reference crops, and generated tasks can make the intended action obvious.
4. **ActiView may be too narrow.** It evaluates view selection, not general tool routing among OCR, web search, clarification, abstention, and answer.
5. **TIR-Bench may be unsuitable for abstention research.** Its tasks are designed to require tool manipulation, so always using a tool can look artificially optimal.
6. **VISUALTOOLBENCH relies on LLM judging.** Its rubric score is useful diagnostically but weak as the sole ground truth. The paper itself describes rubric-based automatic grading rather than exact answer checking. [Evaluation](https://www.alphaxiv.org/abs/2510.12712?page=5)
7. **Prompt engineering may dominate the result.** A better system prompt can change tool-call rates more than the proposed router.
8. **Tool choice and answer quality are confounded.** A tool call adds tokens, intermediate images, and additional reasoning opportunities.
9. **The web version is operationally fragile.** Search results, page availability, API pricing, caching, and regional access can change.
10. **The learned intervention may not be needed.** A simple confidence threshold or fixed rule may match a trained router.
11. **Negative results may be uninterpretable.** Failure could result from weak OCR, poor crop parameters, bad tool interfaces, or the base VLM rather than from the decision hypothesis.
12. **API costs may grow unexpectedly.** [MMSearch-Plus](https://www.alphaxiv.org/abs/2508.21475) allows up to 20 search rounds, and its authors report long trajectories and many retrieved items. [Search budget](https://www.alphaxiv.org/abs/2508.21475?page=6)
13. **The contribution may collapse into a benchmark audit.** That is acceptable only if the failure taxonomy and evaluation protocol are rigorous enough to stand independently.

## K. Final classification

# RESERVE

The area is not rejected because a defensible undergraduate question remains: **can a multimodal system predict the marginal value of a visual action under controlled, deterministic conditions, and can its failures be decomposed into perception, selection, execution, and reasoning errors?**

However, the broad candidate should not proceed as “learn when to use tools.” That claim is already substantially covered by [AdaTooler-V](https://www.alphaxiv.org/abs/2512.16918) and related 2026 work. Candidate 2 is worth a deeper audit only in the restricted form of a local, objective, counterfactual evaluation using [ActiView](https://www.alphaxiv.org/abs/2410.04659) and a carefully selected deterministic subset of [TIR-Bench](https://www.alphaxiv.org/abs/2511.01833), with web search, large-scale RL, and LLM-as-judge evaluation excluded from the core thesis.
